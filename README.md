# Pano Sharp Studio

Prompt -> GPT Image 2 equirectangular panorama -> perspective crop rig -> Apple SHARP per-crop Gaussian splats -> merged `world.ply`.

This project is a local research app for the exact pipeline you described. It generates a 2:1 panorama, splits it into SHARP-friendly perspective views, runs Apple SHARP on each face, and splices the resulting PLY files into one approximate Gaussian splat world.

## The `ml-sharp` install question

Apple's README currently recommends:

```bash
conda create -n sharp python=3.13
pip install -r requirements.txt
```

For this project, we do not use Conda. We install SHARP through `uv` instead.

That works because the upstream `apple/ml-sharp` repository is already pip-packaged:

- it contains a `pyproject.toml`
- it exposes a `sharp` CLI entry point
- its `requirements.txt` is generated by `uv`

This repo pins `apple/ml-sharp` as a Git dependency in `pyproject.toml`, so `uv sync` installs both the web app and SHARP into the same `.venv`.

Verified in this workspace on Apple Silicon on April 24, 2026:

```bash
uv sync
uv run sharp --help
```

## Setup

### 1. Install everything with `uv`

```bash
uv sync
cp .env.example .env
```

Set `OPENAI_API_KEY` in `.env`.

Notes:

- The project pins Python `3.13` because SHARP upstream recommends Python 3.13.
- The first `uv sync` is large because it downloads Torch, TorchVision, `gsplat`, and SHARP itself.
- The first `sharp predict` run also downloads the SHARP model checkpoint into `~/.cache/torch/hub/checkpoints/`.

### 2. Verify the runtime

```bash
uv run pano-sharp-doctor
```

Or use the helper:

```bash
./scripts/install_sharp.sh
```

That helper now just runs `uv sync` and verifies `uv run sharp --help`.

### 3. Run the web app

```bash
uv run uvicorn app.main:app --reload --port 8080
```

Open `http://localhost:8080`.

If you change the Gaussian splat viewer frontend, rebuild the Vite bundle:

```bash
npm install
npm run build
```

### 4. Run from the CLI

```bash
uv run pano-sharp "A cozy futuristic AI research lab inside a glass geodesic dome on a rainy mountain night"
```

Use `--reference-image-url` or `--reference-image-path` one or more times to guide GPT Image 2 with style, material, or composition references:

```bash
uv run pano-sharp \
  "A candlelit observatory carved into a salt cliff above a bioluminescent sea" \
  --quality high \
  --reference-image-url https://example.com/brass-instruments.jpg \
```

## Why the panorama is split

Apple SHARP is built for single perspective images, not raw 2:1 equirectangular panoramas. Equirectangular images compress and distort content heavily near the poles, so feeding the panorama directly into SHARP is likely to produce unstable geometry.

Instead, this app:

1. Generates one seamless panorama with `gpt-image-2`.
2. Extracts perspective crops from that sphere.
3. Runs SHARP on each crop independently.
4. Rotates each local PLY back into a shared panorama frame.
5. Merges the vertices into `world.ply`.

## Current pipeline

1. Generate a `3840x1920` panorama with `gpt-image-2`.
2. Save `runs/<job>/panorama.png`.
3. Split the panorama into either:
   - `horizon8`: 8 crops around the equator.
   - `sphere24`: 8 yaw positions x 3 pitch rows, default.
4. Run `sharp predict -i runs/<job>/faces -o runs/<job>/sharp_plys`.
5. Merge the per-face PLY files into `runs/<job>/world.ply`.
6. Inspect the 360 preview, then build the high-fidelity render when the scene is worth keeping.
7. Open previous high-fidelity renders from the **Load Scene** thumbnail picker.

## High-fidelity render viewer

The main page keeps the 360 preview viewer fast and lightweight. Use **Build high-fidelity render** to run SHARP if needed and export the browser-ready render at `runs/<job>/viewer/world.splat`.

Large worlds can create hundreds of MB of viewer data and may take time to generate and load. A small `preview_thumbnail.jpg` is created as soon as each preview is generated; the Load Scene picker lists only completed high-fidelity renders that already have that thumbnail.

The viewer frontend is built with Vite from `frontend/splat-viewer.js` and uses `@mkkellogg/gaussian-splats-3d` plus `three`. The built bundle is served from `app/static/dist/splat-viewer.js`; do not vendor Three.js manually.

## OpenAI image settings

The app defaults to `quality="high"` for less grainy panoramas:

```python
client.images.generate(
    model="gpt-image-2",
    prompt=build_panorama_prompt(prompt),
    size="3840x1920",
    quality="high",
    output_format="png",
)
```

`3840x1920` is valid for GPT Image 2 because it satisfies the published constraints:

- maximum edge <= `3840`
- both edges multiples of `16`
- aspect ratio no more than `3:1`
- total pixels between `655,360` and `8,294,400`

If you provide reference images, the app downloads/uploads and normalizes them to PNG, then calls `client.images.edit(...)` with the same prompt, size, quality, and output format. References are used when generating a new preview.

## Implementation notes

### Crop rig

`app/equirect.py` performs equirectangular-to-perspective extraction directly with NumPy and PIL. Each crop stores a `world_from_camera` rotation matrix in `faces.json`.

### SHARP inference

`app/sharp_runner.py` shells out to:

```bash
sharp predict -i <faces_dir> -o <ply_dir>
```

Because SHARP is installed into the same `uv` environment, `SHARP_BIN=sharp` is usually enough.

### PLY splice step

`app/ply_merge.py` preserves SHARP's vertex schema with `plyfile`, rotates each crop-local cloud into the panorama frame, and applies a simple spherical Voronoi clip to reduce duplicate splats near seams.

## Known limitations

- A single AI-generated panorama does not contain real multi-view parallax, so geometry can tear or collapse.
- Per-crop SHARP predictions can disagree in scale; this merger does not yet solve scale alignment.
- Zenith and nadir regions are still hard because equirectangular panoramas distort them most.
- SHARP licensing and model licensing should be reviewed before commercial use.
